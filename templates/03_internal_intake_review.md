# 내부용 — 수주 가능성 판정 체크리스트

> **사용자:** 영업 담당 + 개발 담당\
> **목표:** 견적서 발행 전에 요구사항과 기술적 작업 가능성을 구분하고, 추가 질문을 최소화한다.

## 1. 의뢰 접수

- [ ] 실제 고객 홈페이지 URL 확인
- [ ] 고객이 원하는 검색 결과 **스크린샷·검색어·PC/모바일** 확인
- [ ] 원하는 결과가 정말 `ListItem` 캐러셀인지, 광고·네이버 플레이스·사이트링크·기타 기능인지 구별
- [ ] 대상 콘텐츠(목록/상세 페이지/원본 이미지) 존재 여부 확인
- [ ] 홈페이지 소유·수정 권한 보유자 확인 (비밀번호 수집 금지)
- [ ] 작업 희망 범위·기한·예산 확인

## 3. 작업 적합성 판정

- [ ] **READY**: 필요한 콘텐츠와 수정 경로가 확인되어 견적 가능
- [ ] **NEED_INFO**: 콘텐츠·권한·플랫폼 정보가 더 필요
- [ ] **CUSTOM_QUOTE**: 자체 개발·복잡한 통합으로 별도 기술 견적 필요
- [ ] **OUT_OF_SCOPE**: 목적 결과가 제공 가능한 작업과 다르거나 수행 불가

## 4. 고객 설명 및 계약서 반영

- **우리가 제공하는 것:** 구조화 데이터·SEO·이미지 수정, 적용 및 기술 검증 등 합의된 범위
- **우리가 보장하지 않는 것:** 네이버의 실제 캐러셀 노출, 노출 시기, 검색 순위, 클릭 수 또는 매출
- **검수 기준:** HTML 마크업·공개 콘텐츠·URL·이미지·메타태그 일치, 주요 페이지 회귀 테스트
- **변경 전 조건:** 고객 승인, 백업/롤백, 배포 담당자, 운영 중 수정 범위 합의
- **병원 등 규제 업종:** 사실관계, 사진·문구 사용 권리, 의료광고 검토 책임자 사전 지정

## 5. Codex/Toolkit 연동 시

- 첫 신청서는 사람이 읽기 쉬운 텍스트로 받는다.
- 공개 URL 분석 결과를 함께 보관하되, **관찰한 사실과 고객이 주장한 환경 정보를 분리**한다.
- 누락된 정보만 자동으로 추가 질문하도록 설계한다.
- 계약 후 기술정보를 보강하며, 비밀번호·환자정보·개인 인증키는 분석 결과 JSON에 기록하지 않는다.
- 읽기 전용 분석과 실제 수정 작업을 분리하고, 고객의 명시적인 배포 승인이 있을 때만 수정한다.
